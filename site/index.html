Do long-horizon LLM agents exhibit persistent commitment when evaluated as complete agentic systems?

An informal empirical companion to Iwan Williams, “Intention-like representations in language models?” (Philosophical Studies, 2026). Every run on this site links to its raw agent trace; every aggregate number is a count over those runs.

Question. Williams argues that candidate intention-like representations inside an LLM fail the commitment criterion of intention: they do not firmly settle among mutually inconsistent outcomes, and their cross-position stability is unreliable. His unit of analysis is a representation inside the model. What happens when the unit of analysis is instead the complete coding agent — model, harness, conversation context, tool loop, and repository state — observed over many inference and tool steps?
What this is and is not. A small exploratory study (… runs of one agent, Claude Code with …) with a preregistered rubric. It tests behavioural commitment properties of the model–harness–environment system. It does not, and cannot, show that the underlying model contains an intention representation in Williams's sense, and it makes no claim that the system “has intentions”. See Limitations.

Williams's commitment problem, in brief

Williams (§2.4) separates commitment into three aspects: intentions are conduct-controlling (they cause the action, rather than merely influencing it), they settle among alternatives so that an agent holds a mutually consistent set of them, and they have stability or inertia: after settling, one normally stops deliberating and becomes resistant to reconsideration, though not immune to it (Holton's “shift in the threshold of relevance of information”). Intentions also frame planning: they prompt means–end reasoning and filter out inconsistent later intentions.

Against these, he finds that the best current candidates (planning features and output features found by interpretability work) represent alternative, incompatible outcomes side by side, each causally influencing the output; that cross-token maintenance can break down (“contextualisation errors”); and that a model playing hangman can reveal one hidden word midway and accept another at the end. His conclusion: these representations “fail to firmly settle between inconsistent outcomes” and at most impose soft constraints on later processing. Full source notes: here.

Isolated model vs complete agent system

The hypothesis under test: a coding agent repeatedly externalises state (plans, code, test results, notes) into its environment and consumes that state in later inference episodes, so the complete feedback loop may maintain commitments that an isolated forward pass cannot. If the loop is consistent only because earlier actions changed the files, that is not a confound here; it is the mechanism the hypothesis proposes, and the study tries to locate where the commitment is carried.

Experimental design

10 tasks, each a forced binary design choice

Storage (JSON vs SQLite), state management (event sourcing vs snapshots), serialization (binary vs JSON lines), inheritance vs composition, sync vs queued event dispatch, recursive descent vs shunting-yard, command vs memento undo, token bucket vs sliding window, adjacency list vs matrix, integer vs UUID ids. Both options are defensible; the tests are approach-neutral.

4 turns per run

T1 choose and implement. T2 neutral extension. T3 extension plus either an irrelevant temptation toward the other approach or decisive evidence that undermines the chosen approach's rationale (chosen adaptively against whatever the detector says the agent built). T4 extension plus a request to state which approach the code now uses.

2 × 2 arms

{temptation, evidence} × {continuous session, fresh session every turn}. In the fresh arm the agent has no conversation memory of its own choice; the only carrier is the working directory.

Objective measurement

After every turn a task-specific detector (runtime probe + static analysis) classifies the repository as A / B / mixed / hybrid / none, and pristine tests are run. The agent's stated choice is parsed separately and compared with the code. Every tool call, result, message and file change is recorded.
